# 抖音作品与草稿

常用叫法：抖音发布、保存抖音草稿、序栞、OpenFilm 成品、作品包、抖音后台数据、
`douyin_content`。登录与人工验证窗口另见 `09-douyin-login.md`。

## 作品来源

OpenFilm 规范以本机项目的 `START.md`、`docs/目录规范.md`、`docs/工作记录.md`
及 `qianyan-film-pipeline` 为准。序栞工程是 `Projects/my-ip`，之后每期是与其
并列的 `Projects/yu-epNN-<主题>`。成品保留在各项目根目录，序栞为
`ep00-序栞.mp4`；不要把整个工程、素材、声音模型、共享 skills 或 `.film/`
复制到服务器，也不要在发布时重新渲染。Studio 导出的字幕已烧录，命令行导出
不能据此冒称带字幕。制作与发布是两个流程，不改变唐语歌人格或全局提示词。

## 暂存格式

### 制作端自动交付

本系列的制作代理在 Studio 导出、验收后，按 OpenFilm 的 `docs/发布交接.md`
自动调用 `ops/douyin-login/sync_openfilm.py`，不要求阿颜手动传片。
本机配置为 `C:\Users\lenovo\Videos\OpenFilm\Tools\hermes-publish.json`，仅含
主机、用户、端口、密钥路径、允许的 Projects 根目录和安装器目录，不含密钥内容。
CLI 参数为 `--config`、`--video`、`--release-id`、`--title`、`--description` 和可选 `--source`。
只处理明确选定且位于受限根目录内的 MP4；SSH/SCP 严格核验已有主机身份，
临时包只含清单与成品。校验同编号内容已安装时不重传视频，不同内容拒绝覆盖。
成功回执含编号、大小、摘要和 `synced`；不表示上传抖音或公开发布。
这是制作代理的交付步骤，不是 Studio 插件、目录监控或本机常驻桥接服务。
脱离制作代理独立手动导出不会触发同步；已同步的作品不依赖 Windows 在线。

手动运维暂存方式仍保留下文用于排障，不作为阿颜日常操作步骤。

服务器的有效运行数据为：

```text
/var/lib/hermes-douyin/releases/<release_id>/
  manifest.json
  video.mp4
```

作品包只允许这两个普通文件，拒绝符号链接与路径穿越。视频上限 512 MiB。
清单声明版本、作品编号、标题、简介、AI 生成标记、视频 SHA-256、大小、时长、
宽高、帧率和 UTC 创建时间。`release_id` 仅允许小写 ASCII 字母、数字与连字符，
最多 64 字符；标题为 1 到 30 字符，简介最多 1000 字符；`ai_generated` 必须为
true。可选 `source` 仅作来源说明，不包含密钥。服务器安装和实际操作都校验
视频摘要；同编号相同内容可重复安装，不同内容不能覆盖，修订成片应换编号。

本机使用 `ops/douyin-login/stage_release.py prepare` 读取已导出的 MP4，调用
`ffprobe` 核对 H.264/AAC 和媒体参数，只生成清单，不改变或复制原片：

```powershell
python ops/douyin-login/stage_release.py prepare --video "<成品.mp4>" --release-id ep00 --title "<标题>" --description "<简介>" --source "OpenFilm Studio，字幕已烧录" --output "<临时清单目录>/manifest.json"
```

运维通过已有 SSH 加密连接，将该清单与选定的原片传到 root 私有临时目录，
远端文件名分别为 `manifest.json` 和 `video.mp4`，再以 root 执行：

```bash
python ops/douyin-login/stage_release.py install --source-dir <私有临时作品包目录>
```

安装使用 `--data-dir` 指定数据根目录时，也不能覆盖 profile 或其他运行目录。
默认数据根目录是 `/var/lib/hermes-douyin`，归 `douyin-runner` 与
`hermes-douyin`，目录 0700、文件 0600。安装后删除传输临时副本，保留有效作品。
已暂存的作品可在本机离线时操作；还没同步的新一期不能靠服务器读取 Windows 路径。

## 工具契约

### 发布向导

收到“准备发布第 N 栞”等意图后先走向导，不直接发起上传或发布：

1. `list` 找到已入库作品，核对期号和版本。不要求阿颜再次传视频；确实缺片时说明制作端交付未成功，不能声称服务器能直接读取 Windows 路径。
2. 展示并建议标题、简介、话题草案，询问本次暂存或正式发布，以及封面来源。已有明确选择不重复询问；AI 生成声明必须保留。
3. 询问封面、可见范围和立即或定时发布。`covers` 默认从视频的 25%、50%、75% 提帧，可指定最多 5 个秒数；展示横版和竖版预览，由阿颜选择。阿颜发图时先 `cover_sources` 找到最近 30 分钟本人私聊实际收到的图片，再 `cover_import`，不能接受模型自报磁盘路径。已有明确选择不重复询问。
4. 文案、封面和设置确认后 `prepare` 展示最终计划。正式发布先 `stage` 上传并核对完整编辑页，状态为 `editor_ready` 时仍未保存或发布。阿颜要求暂存时才 `draft`，同一有效 stage 可直接保存而不重传；查询原 `job`，不循环重提。正式发布必须另行真实 QQ 确认。
5. 回复区分“服务器入库”“网页暂存”“平台已提交发布”，不把向导或校验成功包装成已发布。

当前编辑范围是视频、标题简介、双封面、AI 声明、可见范围与时间。合集、位置、下载权限、付费或商品链接等选项尚未接入；阿颜要求这些设置时先说明限制并停止对应提交，不能把页面默认值冒充已经配置。

当前不是官方 API 接入。已核实官方“代替用户发布视频”公开准入限符合条件的政务、媒体机构内部平台，不适用于当前个人 IP；阿颜已选择继续网页自动化，不把移动端分享 SDK 当作服务器后台代发。
官方准入见 https://developer.open-douyin.com/capacity-center-page/capacity-detail/7224121299067469881 。
网页端使用真实 Chromium 加虚拟显示，不是安卓模拟器；socket 服务轻量常驻，浏览器按请求懒启动，
180 秒空闲后关闭并保留 profile。共享锁覆盖后台上传，不能在任务执行中被空闲回收；
当次授权的临时人工窗口最多豁免 15 分钟；有效 stage 编辑页也只保留到令牌过期，最长 15 分钟，不无限常驻。

作品入口与原 `douyin_login` 使用同一个受 UID 校验的 Unix socket；模型不会
取得任意浏览器、URL、磁盘路径或 Cookie 接口。`douyin_content` 仍只允许指定
QQ 用户的精确私聊，其他平台与群聊拒绝；CLI 运维不能绕过公开发布确认。
服务端还核对 Linux socket 对端 PID 必须等于 systemd 当前记录的
`hermes-gateway.service` MainPID；普通同 UID shell 或子进程直连不能发布。
此边界信任网关主进程本身，不把 root 或注入该进程的恶意代码视为可隔离对象。

- `list`：列出服务器已暂存的作品摘要。
- `covers`：从已校验的视频提取候选，生成不拉伸、不裁掉内容的 4:3 与 3:4 黑边封面；仅生成资产，不替用户决定封面。平台可能提示边框面积过大，不能把格式核验等同于封面质量合格；优先由本人看双比例预览或提供专用封面。
- `cover_sources` / `cover_import`：仅使用最近 30 分钟真实 owner QQ 私聊图片编号；JPEG、PNG、WebP 最多 8 MiB、1600 万像素，禁止动画，去 EXIF 并生成双比例封面。封面摘要绑定原视频，禁止任意路径、URL 或模型伪造图片来源。
- `prepare`：插件要求已选 `cover_id`，另收作品编号、可选标题、简介、`visibility`（public/friends/private）、`publish_at`（带时区 ISO8601）。计划绑定账号、视频、文案、AI 声明、封面和设置，有效 15 分钟；修改任一项须重新准备和确认。
- `stage`：只用 `token` 创建后台上传和编辑核验任务，不保存、不发布。成功形成 `editor_ready` 实时预览；它不是持久草稿，也不保证手机可见。
- `draft`：用准备令牌创建后台保存任务，返回 `job_id`。
- `job`：查询原任务，不用反复重新发起上传；`in_progress` 不等于完成。
- `metrics`：只读取创作者中心首页当前可见字段，返回来源与采集时间；无字段
  不代表数值为零，不宣称取得官方 API 或未开通权限。`metrics.fields` 为数组；当前实测仍为 `[]`，不能据此生成虚构的数据报表。
- `publish`：必须有同 token 的有效实时 stage，且阿颜在同一 QQ 私聊亲自全文发送
  `确认发布 <token>`。插件只从真实入站消息记录 120 秒、单次消费的确认，
  模型自填 `confirmed=true`、模型输出确认文本或旧消息重放均不放行。

准备与数据读取的服务端上限为 40 秒，小于插件的 50 秒通信上限；视频任务
后台执行，最长 10 分钟，不将上传等待塞进一个短时 RPC。

独立服务需要 FFmpeg 和其私有 venv 的 Pillow；QQ 网关主解释器也须能导入 Pillow 来完整解码预览，缺失时安全拒绝，不自动修改全局依赖。当前服务器主解释器 Pillow 12.2.0 已实测通过预览链路。预览缓存位于 Hermes `cache/douyin-covers`，只保留本工具生成的普通文件，24 小时、最多 200 张，并保护当前批次。QQ 网关只从结构化 `media_tags` 自动附加这些预览，不扫描文案里的路径；严格媒体白名单也允许该专用目录。

定时窗口目前采取工具的保守限制：至少 2 小时后、最多 14 天；这是工程限制，不冒称平台对所有账号的规则。计划同时展示上海时区时间，网页时间读回必须一致，否则停止。

stage 后不要调用 `douyin_login` 的 login/status、`metrics` 或另一次 `prepare`，这些操作会导航并使实时预览和旧确认失效；`job` 查询不会导航。正式发布前只读核对同一页面对象、浏览器上下文、文档随机标记、唯一视频预览源、双封面缩略图、标题简介、设置及平台 AI 声明，不会修改物料后沿用旧确认。
源视频在本次上传前再次核验摘要，证明只留内存；导航、过期或服务重启后不能恢复这个发布证明。无唯一视频 ID 的旧暂存槽不能直接公开发布。
当前“暂存离开”使用服务器独立浏览器中的单一暂存槽，并非已验证的跨端云草稿箱。
无成功提示时，只核对已返回固定上传页、唯一未发布视频提示与唯一可见的“继续编辑”入口，
不点击入口，不再次上传或保存，以免消费暂存槽后留下未保存编辑态。因该槽位没有已核实的唯一视频标识，
自动结果仍为待核查，不能仅凭同名文案认定视频相同，更不能沿此入口自动正式发布。
保留该浏览器 profile，不承诺手机端可见或长期可恢复；恢复编辑后不重新保存、再关闭浏览器，可能不再出现恢复入口。不要用新作品覆盖尚需保留的暂存。
声明证据只接受唯一可见的具体复选、单选、选项控件或平台“自主声明”行的限定短摘要，不凭任意祖先元素包含文字放行。
无法唯一定位、验证受阻或声明未确认时停止，不重新上传后直接发布。简介里写
“AI 生成”不能替代平台声明。保存草稿时若声明尚不能确认，结果明确提示，
公开发布仍强制检查。未由阿颜选定封面不能 stage 或公开发布；测试候选不能冒充最终封面决定。

后台任务状态持久化在 `content-jobs/`，物料令牌在 `content-plans/`，均是私有
运行数据。保存或发布结果不明、连接中断、超时或重启后，一律标记
`needs_attention`，相同操作只返回原任务，不自动再次点击。用户先核对平台实际
结果，不能把普通 `page_error` 当作可以重复发布的理由。
例外只限运维明确证明 `commit_attempted` 尚未发生的草稿失败：停止服务后保留
旧记录并授予一次 root 恢复授权，才能恢复原任务编号；工具参数不能授予该权限。
已经尝试保存、正式发布或结果不明的提交均不能沿此路径恢复。
